# 侦察过程复盘

按时间顺序记录「怎么一步步挖出来的」，方便以后复现或扩展。

---

## 阶段 1：确认日历服务是否存在

```bash
python recon/probe_sid.py
```

`serviceLogin?sid=<sid>&_json=true` 对不同 sid 都会返回 `_sign`/`qs`/`callback`，因此可以用 callback 判断服务是否存在：

| sid | callback |
|---|---|
| `calendar` | `https://api.comm.miui.com/calendar/sts` ✅ |
| `micloud` | `https://api.micloud.xiaomi.net/sts` |
| `xiaomiio` | `https://sts.api.io.mi.com/sts` |

结论：日历有独立云服务，STS 挂在 `api.comm.miui.com`（响应头 `Server: calendar-api`）。

## 阶段 2：登录打通

`recon/test_passtoken.py` → `recon/test_sts.py`

`passToken` 能直接换到 `location`，但跟着走一直 401。对比 `sid=xiaomiio` 成功、`calendar` 失败，定位到差异在 `clientSign`：

- ❌ 用 `location` 里的 `nonce` 参数
- ✅ 用登录响应里的**整数 `nonce`**

修正后 200，拿到 `serviceToken`。

## 阶段 3：找数据接口（三条路都试了）

| 手段 | 结果 |
|---|---|
| 猜路径 `recon/probe_paths.py`、`probe_prefix.py`、`probe_versions.py` | 全 404 |
| DNS 爆破 `*.micloud.xiaomi.net` | 没有日历专属域名 |
| APK 字符串 `recon/scan_dex.py` | 只有卡片/节假日接口 |

真正的突破来自**手机侧日志**：

```bash
adb logcat -s "##XLogger##" "CloudRequestHelper"
```

发烧云 SDK 在请求失败时会把完整 URI 打进 `CloudRequestHelper`：

```
E/CloudRequestHelper: HTTP request failed! URI: https://pdc.micloud.xiaomi.net/mic/pdc/v4.1/apps/calendar/spaces/default/records?...
```

同时看到同步流程：`onPerformMiCloudSync → uploadCalendar → uploadEvents → downloadRecords`，
以及 `syncStateVersion 4.1`、`waterMark` 等概念。

## 阶段 4：抓完整参数

成功请求不会打参数，所以故意让请求失败：

```bash
adb shell settings put global http_proxy 127.0.0.1:1
adb shell settings put global http_proxy :0     # 结束后恢复
```

得到完整 query：`_nonce`、`syncToken`、`_count`、`_delta`、`limit`、`_backend`、`_apkversion*`、`signature`。

## 阶段 5：反编译拿签名算法

工具链（都不需要联网装包）：

```bash
adb pull /product/app/MIUIMiCloudSync/MIUIMiCloudSync.apk
tools/buildtools/android-14/dexdump.exe -d recon/dex/sync_classes.dex > recon/sync_dump.txt
python recon/show_method.py recon/sync_dump.txt signature
python recon/dump_method.py recon/sync_dump.txt "Lh0/f;" b
```

栈：`LY/g;->h` → `Lh0/d;->h` → `Lh0/f;->b`

```
items = [METHOD.toUpperCase(), uri.getEncodedPath()]
       + ["k=v" 按 TreeMap 排序]
       + [security]
signature = Base64(SHA1(join(items, "&")))
```

## 阶段 6：解密响应

继续挖 `Lh0/d;->n`：

```
Base64.decode(security, 2)          → AES key
"AES/CBC/PKCS5Padding"
IvParameterSpec(iv)
```

响应 `D` 解密后即业务 JSON。

## 阶段 7：游标自造

`limit`/`syncToken` 同属一套 AES token，密钥就是 ssecurity，
因此可以自己加密数字造出 `limit`，不需要先有一次真实同步：

```python
limit = make_token(key, b"20")   # → 1:<iv>:<ct>
```

## 踩过的坑

1. `clientSign` 的 nonce 来源（整数 vs 参数）
2. 只带签名不带 cookie → 401
3. 参数里有 base64 值（`+` `/` `=`）时，签名用**原始值**，不要 URL 编码
4. 解密结果尾部有填充字节，`json.loads` 会报 `Extra data`
5. `dtend` 可能是 `Long.MAX_VALUE`，要用 `duration` 推
6. `adb` 设备的全局代理会影响整机联网，务必设 watchdog 自动恢复
