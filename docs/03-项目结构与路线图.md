# 项目结构与路线图

## 目录

```
mi-calendar/
├── mi_session.py         ★ 静默登录：passToken → serviceToken / ssecurity
├── mi_calendar_api.py    ★ 底层：签名、请求、AES 解密
├── mi_pull.py            ★ 拉取记录（分页）
├── demo_events.py        打印样例日程（人读）
├── mi_login.py           密码登录（备用）
├── qr_login.py           扫码登录（首次拿 passToken）
├── mi_pdc.py             试验版客户端（被 mi_calendar_api 取代）
├── mi_sign.py            早期签名实验
├── docs/
│   ├── 01-协议说明.md
│   ├── 02-侦察过程.md
│   └── 03-项目结构与路线图.md
├── recon/                侦察与实验脚本、抓包日志、dex
├── state/                凭据（**不要提交、不要外传**）
└── tools/                离线工具：jdk17、build-tools(dexdump)、pycryptodome、adb
```

## 依赖

- Python 3.12，仅用 `requests`
- AES 用本地 `tools/pylibs` 里的 pycryptodome（离线解包，不污染全局环境）
- adb 仅侦察用，日常读写不需要手机

## 用法

```powershell
python mi_session.py calendar   # 查看/续期 token
python mi_pull.py               # 拉取全部记录
python demo_events.py           # 人读格式输出
```

## 数据结构备忘

- 拉取是「全量 + 增量」模型：首次用自造 `limit` 游标，之后用响应里的 `syncToken`
- `watermark` 是时间水位，可存下来做下次增量的起点
- `eventStatus=2` 是墓碑，**不能丢**，否则同步会把删除当成新增

## 路线图

| 阶段 | 内容 | 状态 |
|---|---|---|
| 1 | 登录 + 签名 + 解密 | ✅ |
| 2 | 拉取（含游标自造） | ✅ |
| 3 | 导出 `.ics` | ✅ `mi_ics.py` |
| 4 | 增量同步（syncToken + watermark 持久化） | ✅ `mi_sync.py` |
| 5 | 写入：新增 / 修改 / 删除 | ✅ `mi_write.py`（create / update / delete 全部验证通过） |
| 6 | CLI | 待做 |
| 7 | CalDAV / 服务化网关 | 待做 |

### 写入需要注意

1. 新增：POST 到 `records`，body 为 `contentJson`，需要 `uniqueKey` / `calendarId`
2. 修改：带 `eTag` 做乐观锁，冲突会返回特定 code
3. 删除：写 `eventStatus=2` 墓碑，而不是物理删除
4. 首次验证建议：**新建一条测试日程 → 手机端确认可见 → 立刻删除**

## 安全提醒

- `state/` 里是 `passToken`、`serviceToken`、`ssecurity`，等同于账号凭证
- `state/cred.txt` 是明文的账号密码，建议用完删掉
- `recon/cal_logcat*.txt` 含个人日程 URL 与内容，分享代码前先清掉
- `tools/*.zip` 是下载缓存的安装包（JDK 186MB 等），可随时删
