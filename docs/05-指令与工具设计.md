# 插件指令与工具设计

本文细化 `astrbot_plugin_fever_calendar` 的**指令**（人类用）和 **LLM 工具**（模型用）两部分。
两者共用同一层 `core/service.py`，只是入口不同。

---

## 0. 设计原则

| 原则 | 说明 |
|---|---|
| 序号寻址 | 用户不记 record id。列表结果按会话缓存，后续用「序号」引用，默认 10 分钟内有效 |
| 写操作要确认 | 删除、以及"一次改多个字段"，都要二次确认，防手滑 |
| 时间只认一个时区 | 全部按配置的 `timezone`（默认 `Asia/Shanghai`）解释和展示 |
| 输出稳定 | 列表固定格式，方便用户扫一眼；不用 Markdown 表格（部分平台不渲染） |
| 错误说人话 | 服务端错误码翻译成中文，原始 reason 放在括号里 |
| 指令与工具同源 | 指令和 LLM 工具调用同一个 `CalendarService`，避免两套逻辑漂移 |

---

## 1. 指令总览

统一前缀 `/calendar`，不设中文别名与其它简写。

账号粒度：默认「平台 + 发送者 ID」各自一个账号，各用各的登录态；
`/calendar bind` 可以把多个平台上的身份并到同一个账号。

| 指令 | 作用 | 写操作 |
|---|---|---|
| `/calendar` 或 `/calendar help` | 帮助卡片 | - |
| `/calendar login` | 扫码登录 / 重新登录 | - |
| `/calendar status` | 登录态、记录数、上次同步 | - |
| `/calendar sync` | 手动增量同步（**未实现**） | - |
| `/calendar logout` | 退出并清除本机登录态 | - |
| `/calendar bind [短码]` | 生成短码 / 用短码把当前平台绑到同一个账号 | - |
| `/calendar today` / `tomorrow` / `week` | 按范围列表 | - |
| `/calendar nextmonth` | 下个月（**未实现**） | - |
| `/calendar search <关键词>` | 标题模糊搜索 | - |
| `/calendar show <序号>` | 单条详情 | - |
| `/calendar add <标题> <时间> [选项]` | 新建 | ✅ |
| `/calendar update <序号> [字段=值 ...]` | 修改 | ✅ |
| `/calendar delete <序号>` | 删除（需确认） | ✅ |
| `/calendar confirm <token>` | 执行待确认操作 | ✅ |
| `/calendar export [范围]` | 导出 ics 文件 | - |

> 标「未实现」的是路线图里的设计，当前版本 0.5.0 只上线了其余指令。

## 2. 指令详解

### 2.1 `/calendar login`

流程：

```
用户：/calendar login
Bot ：[二维码图片]
      请用发烧手机「设置 → 发烧账号 → 扫一扫」确认，5 分钟内有效。

（用户扫码后，插件轮询到 location，换 serviceToken 落盘）

Bot ：✅ 登录成功，账号 2342****46，已同步 96 条记录。
```

失败分支：

| 情况 | 回复 |
|---|---|
| 二维码过期 | "二维码已过期，重新发送 /calendar login 即可" |
| sts 返回 401 | "登录被拒（401），可能是设备风控，请重试一次" |
| 已有有效令牌 | "当前已登录，无需重复登录；如需切换账号请先 /calendar logout" |

### 2.2 `/calendar status`

```
用户：/calendar status
Bot ：📅 发烧日历
      账号：2342****46
      令牌：有效（剩余约 29 天）
      本地记录：96 条（事件 95 / 日历 1）
      上次同步：2026-10-23 09:41（12 分钟前）
```

### 2.3 `今天 / 明天 / 本周 / 下月`

```
用户：/calendar today
Bot ：📅 今天（10-23 周五）
      1. 21:00  团队晨会            🔔 提前 15 分钟
      2. 21:15  项目评审会  🔔 提前 30 分钟
      共 2 条
```

规则：

- 按 `dtstart` 排序；带 `rrule` 的展开当日实例
- `eventStatus=2`（墓碑）不显示
- 全天事件排在最前，显示为 `全天`
- 闹钟提醒标 🔔，倒计时标 ⏳，普通提醒标 ⏰
- 超过 10 条只显示前 10 条 + "…还有 N 条，用 /calendar week 查看"

### 2.4 `/calendar search <关键词>`

```
用户：/calendar search 演讲
Bot ：🔍 "演讲" 命中 1 条
      1. 10-23 21:15  项目评审会
```

搜索范围默认未来 90 天 + 过去 30 天，可用 `--all` 搜全部。

### 2.5 `/calendar show <序号>`

```
用户：/calendar show 1
Bot ：📌 团队晨会
      时间：2026-10-23 21:00 – 22:00
      日历：Cloud Calendar
      提醒：提前 15 分钟（闹钟方式）
      重复：无
      地点：—
      id：AygH9CyhKgE
```

### 2.6 `/calendar add`

语法：

```
/calendar add <标题> <时间> [--remind N] [--alarm on|off] [--countdown on|off] [--repeat daily|weekly|monthly] [--location X] [--description X] [--all-day]
```

时间支持：

| 写法 | 解析 |
|---|---|
| `2026-10-24 20:00` | 绝对时间 |
| `明天 15:00`、`后天 9:30` | 相对日期 + 时间 |
| `周五 19:00` | 下一个周五 |
| `今晚 8点`、`明早 7点半` | 口语化 |
| `20:00-21:00` | 区间；只给起点则默认 1 小时 |
| `--all-day 2026-10-25` | 全天事件 |

```
用户：/calendar add 小组会议 明天 14:00-15:00 --remind 10 --alarm on
Bot ：✅ 已创建
      小组会议｜10-24 14:00–15:00｜🔔 闹钟提醒，提前 10 分钟
      序号 1（/calendar update 1、/calendar delete 1 可操作）

用户：/calendar add 抢课 后天 09:00 --remind 30 --countdown on --alarm on
Bot ：✅ 已创建
      抢课｜10-25 09:00–10:00｜🔔⏳ 闹钟+倒计时，提前 30 分钟

用户：/calendar add 例会 周五 19:00 --repeat weekly
Bot ：✅ 已创建
      例会｜10-30 19:00–20:00｜每周五｜⏰ 提前 15 分钟
```

#### 重复规则

`--repeat` 接受口语或标准 RRULE：

| 写法 | 转换结果 |
|---|---|
| `--repeat 每天` | `FREQ=DAILY` |
| `--repeat weekly` | `FREQ=WEEKLY;WKST=SU;BYDAY=<起始日星期>` |
| `--repeat weekly五` | `FREQ=WEEKLY;WKST=SU;BYDAY=FR` |
| `--repeat 每月` | `FREQ=MONTHLY;BYMONTHDAY=<起始日>` |
| `--repeat 每年` | `FREQ=YEARLY` |
| `--repeat FREQ=WEEKLY;UNTIL=20261231T000000Z` | 原样使用 |

结束条件用 `--repeat-until 2026-12-31` 或 `--repeat-count 10` 追加 `UNTIL=` / `COUNT=`。

**重复事件的支持边界**（已实测）：

| 能力 | 状态 |
|---|---|
| 读取现有重复规则 | ✅ 原样返回 `rrule` |
| 新建重复事件 | ✅ 已验证（`FREQ=WEEKLY;COUNT=4` 写入后读回一致） |
| 修改整个系列（改 `rrule` / 标题 / 提醒） | ✅ 与普通事件同一接口 |
| 导出 ics | ✅ `RRULE` 已写入 |
| 修改/删除**单次实例** | ✅ 写「例外记录」实现，手机端肉眼确认：改的那次标题变了，删的那次不显示 |

插件遇到「只改这一次 / 只删这一次」时，写一条例外记录：

```json
{
  "originalServerId": "母事件 id",
  "originalInstanceTime": 1792890000000,
  "originalAllDay": 0
}
```

- 改：例外记录带新字段（标题/时间/提醒），`rrule` 置空
- 删：例外记录带 `eventStatus: 2`

删除时手机上会看到该时段的事件变成「已取消」，而不是物理消失。

### 2.7 `/calendar update <序号>`

支持字段：`标题`、`时间`、`提醒`、`闹钟开关`、`倒计时开关`、`重复`、`地点`、`描述`。

```
用户：/calendar update 1 --remind 30
Bot ：✅ 已修改：小组会议｜提醒 提前 30 分钟

用户：/calendar update 1 --alarm off
Bot ：✅ 已修改：小组会议｜闹钟提醒 已关闭

用户：/calendar update 1 --countdown on --alarm on
Bot ：✅ 已修改：抢课｜🔔⏳ 闹钟+倒计时

用户：/calendar update 1 --time 明天 16:00
Bot ：✅ 已修改：小组会议｜10-24 16:00–17:00
```

两个开关独立，四种组合都合法：

| 指令 | `need_alarm` | `is_countdown_reminder` |
|---|---|---|
| `--alarm off --countdown off`（=`--通知`） | false | false |
| `--alarm on` | true | false |
| `--countdown on` | false | true |
| `--alarm on --countdown on` | true | true |

实现要点：读当前记录 → 改字段 → 带 `eTag` 调 `/records/{id}/update` → 回写新 `eTag` 到本地缓存。
改提醒方式时**只改 `agenda_info` 里的两个布尔位**，其余键（`is_ai`、`extend_agenda_type`）原样保留，避免破坏 AI 提醒等设置。

### 2.8 `/calendar delete <序号>`

```
用户：/calendar delete 1
Bot ：⚠️ 确认删除「小组会议」（10-24 14:00）？
      回复 /calendar confirm 7f3a 执行，60 秒内有效。

用户：/calendar confirm 7f3a
Bot ：🗑 已删除「小组会议」
```

确认 token 绑定 `用户 + 记录 id + 操作类型`，一次性、60 秒过期。

### 2.9 `/calendar export`

```
用户：/calendar export
Bot ：[calendar_export.ics]  95 个事件，可直接导入 Apple 日历 / Thunderbird
```

范围参数：`--this-month`、`--this-year`、`--all`（默认全部）。

## 3. 序号机制

| 项 | 规则 |
|---|---|
| 缓存位置 | 会话级 KV：`list:{umo}` |
| 内容 | `[{idx, id, eTag, title, start, end}]`，最多 20 条 |
| 有效期 | 10 分钟，或用户发下一条列表时覆盖 |
| 失效提示 | "列表已过期，请先 /calendar today 重新获取" |
| 写后刷新 | 修改/删除后同步更新缓存里的对应项，避免序号错位 |

## 4. LLM 工具

工具面向"自然语言"，所以描述要写清楚**什么时候用**、**参数怎么填**。

### 4.1 工具清单

| 工具名 | 用途 | 写操作 |
|---|---|---|
| `list_calendar_events` | 查某天/某范围的日程 | - |
| `create_calendar_event` | 新建日程 | ✅ |
| `update_calendar_event` | 改日程（标题/时间/提醒/闹钟） | ✅ |
| `delete_calendar_event` | 删除（返回确认 token，需用户确认） | ✅ |

### 4.2 定义示例（装饰器风格）

```python
@filter.llm_tool(name="create_calendar_event")
async def create_calendar_event(
    self,
    event: AstrMessageEvent,
    title: str,
    start: str,
    end: str = "",
    remind_minutes: int = 15,
    alarm: bool = False,
    countdown: bool = False,
    recurrence: str = "",
    location: str = "",
):
    """在用户的发烧云日历里创建一条日程。当用户说"提醒我…""安排…""加个日程"时调用。

    Args:
        title(string): 日程标题，例如"交作业"
        start(string): 开始时间，ISO 格式（2026-10-24 15:00）或自然语言（明天下午三点）
        end(string): 结束时间，可留空，留空默认开始后 1 小时
        remind_minutes(number): 提前多少分钟提醒，默认 15；传 0 表示不提醒
        alarm(boolean): 是否开启闹钟提醒（响铃），默认 false
        countdown(boolean): 是否开启倒计时提醒，默认 false；两个开关可以同时开
        recurrence(string): 重复规则，可填"每天""每周五""每月"或标准 RRULE（FREQ=WEEKLY;BYDAY=FR），不重复则留空
        location(string): 地点，可留空
    """
```

```python
@filter.llm_tool(name="list_calendar_events")
async def list_calendar_events(self, event, range: str = "today"):
    """查询用户的发烧云日程。

    Args:
        range(string): 查询范围，可选 today / tomorrow / week / month，默认 today
    """
```

```python
@filter.llm_tool(name="update_calendar_event")
async def update_calendar_event(
    self, event, keyword: str, field: str, value: str
):
    """修改一条已有日程。用户说"把 X 的提醒改成 30 分钟""关掉 Y 的闹钟""把 Z 换成倒计时"时调用。

    Args:
        keyword(string): 用于定位日程的标题关键词
        field(string): 要改的字段，可选 title / time / remind / alarm / countdown / location
        value(string): 新值；alarm / countdown 用 on/off，remind 用分钟数，time 用自然语言时间
    """
```

```python
@filter.llm_tool(name="delete_calendar_event")
async def delete_calendar_event(self, event, keyword: str):
    """删除一条日程。必须先向用户复述标题让用户确认，再调用本工具。

    Args:
        keyword(string): 日程标题关键词
    """
```

> 注意：`Args:` 段是硬性要求，缺了会导致参数被丢；类型只能是 `string / number / object / boolean / array`。

### 4.3 工具返回值设计

工具返回**给模型看的结构化文本**，不是直接发给用户的消息：

| 场景 | 返回 |
|---|---|
| 成功创建 | `OK id=Ayh... title=小组会议 start=2026-10-24 14:00 remind=10 alarm=true` |
| 命中多条 | `AMBIGUOUS candidates=[1]小组会议 10-24 14:00; [2]小组会议 10-25 09:00` |
| 未找到 | `NOT_FOUND keyword=演讲` |
| 需要确认 | `NEEDS_CONFIRM token=7f3a target=小组会议 10-24 14:00` |
| 令牌失效 | `AUTH_EXPIRED 请提示用户执行登录` |

模型据此组织自然语言回复，例如：

```
用户：帮我把演讲那个的闹钟关了
Bot ：找到「项目评审会」（今天 21:15），已关闭闹钟提醒，
      30 分钟前的普通通知仍然保留。
```

### 4.4 指令与工具的分工

| 场景 | 走哪条 |
|---|---|
| 用户明确知道要干嘛、要精确控制 | 指令更稳（参数显式） |
| 用户口语化、信息不全 | 工具 + 模型补全 |
| 批量/复杂条件 | 工具（模型可以多次调用） |
| 需要严格防误操作 | 指令 + 二次确认 |

两者都调用 `CalendarService`，保证"同样的话，两种入口结果一致"。

## 5. 提醒方式（两个独立开关，四种组合）

发烧日历界面上是**两个开关**：闹钟提醒、倒计时提醒，互不排斥，四种组合都被实测确认可用。

| 组合 | `need_alarm` | `is_countdown_reminder` | 展示 |
|---|---|---|---|
| 仅通知 | false | false | `⏰ 提前 15 分钟` |
| 仅闹钟 | true | false | `🔔 闹钟，提前 15 分钟` |
| 仅倒计时 | false | true | `⏳ 倒计时，提前 15 分钟` |
| 闹钟 + 倒计时 | true | true | `🔔⏳ 闹钟+倒计时，提前 15 分钟` |

数据位置：

- **提前多久** → `reminders` 数组（可多条，如 15 和 0）
- **闹钟开关** → `agenda_info.need_alarm`
- **倒计时开关** → `agenda_info.is_countdown_reminder`

指令写法（两个开关独立控制）：

```
--alarm on|off      --countdown on|off      --通知（等于两个都关）
```

写回时必须**保留 `agenda_info` 的其他键**：

```python
ag = json.loads(old_agenda_info)
ag["need_alarm"] = alarm             # bool
ag["is_countdown_reminder"] = countdown  # bool
# is_ai / extend_agenda_type 等原样保留
```

否则会把「AI 提醒」等设置一并抹掉。

展示时优先显示特殊提醒方式：

| `agenda_info` | `reminders` | 展示 |
|---|---|---|
| 倒计时 | 30 分钟 | `⏳ 倒计时，提前 30 分钟` |
| 闹钟 | 15 分钟 | `🔔 闹钟，提前 15 分钟` |
| 通知 | 15 分钟 | `⏰ 提前 15 分钟` |
| 任意 | 空 | `无提醒` |

## 6. 输出模板

### 列表项

```
{序号}. {HH:MM}  {标题}{标记}   {提醒描述}
```

标记：`🔔` 闹钟提醒 / `⏳` 倒计时 / `⏰` 普通通知 / `📌` 全天

### 提醒描述

| 数据 | 展示 |
|---|---|
| `is_countdown_reminder=true` + `reminders=[{minutes:30}]` | `⏳ 倒计时，提前 30 分钟` |
| `need_alarm=true` + `reminders=[{minutes:15}]` | `🔔 闹钟，提前 15 分钟` |
| `need_alarm=false` + `reminders=[{minutes:30}]` | `⏰ 提前 30 分钟` |
| `reminders=[]` | `无提醒` |

## 6. 错误映射

| 来源 | 回复 |
|---|---|
| `401` | 登录已失效，请 `/calendar login` 重新扫码 |
| `10016 缺失必选参数` | 内部参数错误，已记录日志（不暴露给用户细节） |
| `10008 参数错误` | 这个时间/参数我没理解，换个说法试试 |
| 网络超时 | 网络不太好，已重试 2 次仍失败，稍后再试 |
| 记录被别处删除（404/空） | 「{标题}」已经不在了，可能刚在手机上删掉了 |
| eTag 冲突 | 这条日程刚被改过，我先刷新一下，请再操作一次 |

## 7. 权限

| 角色 | 权限 |
|---|---|
| 白名单用户（配置 `allowed_users`） | 全部指令与工具 |
| 非白名单 | 只读：`今天/明天/本周/搜/查看`；写操作提示"没有权限" |
| 未登录 | 只提示 `/calendar login` |

群聊里默认只读，私聊可写（可配置）。
